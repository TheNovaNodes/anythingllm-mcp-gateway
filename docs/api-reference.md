# API Reference (MCP Tools)

Шлюз `anythingllm-mcp-gateway` предоставляет AI-агентам инструменты для работы с семантической памятью. Взаимодействие происходит по протоколу Model Context Protocol (MCP) через FastMCP SDK.

Ниже представлены все доступные инструменты и их параметры.

## Инструменты (Tools)

### 1. `search_memory`

Гибридный семантический поиск по памяти (vector + lexical, RRF/Weighted).

**Параметры:**

| Параметр | Тип | Обязательный | По умолчанию | Описание |
| :--- | :--- | :---: | :--- | :--- |
| `query` | `str` | Да | - | Поисковый запрос на естественном языке или по ключевым словам. |
| `top_k` | `int` | Нет | `5` | Число возвращаемых результатов (от `1` до `MAX_TOP_K`). |
| `workspace` | `str` | Нет | `None` | Слаговый идентификатор воркспейса для ограничения поиска. |
| `expand_context`| `bool` | Нет | `True` | Расширение найденного пассажа соседними абзацами документа (Context Assembly). |
| `max_token_budget`| `int`| Нет | `None` | Ограничение бюджета токенов вывода. |
| `tier` | `str` | Нет | `None` | Иерархический уровень памяти (например, `episodic`, `semantic`, `procedural`). |

**Ответ (JSON):**

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `query` | `str` | Исходный поисковый запрос. |
| `count` | `int` | Количество найденных результатов. |
| `results` | `list` | Массив найденных документов/фрагментов. |
| `degraded` | `bool` | `True`, если векторный слой был недоступен, и поиск прошел только по лексическому. |
| `layers` | `dict` | Статистика по слоям (количество хитов вектора и лексики). |
| `total_estimated_tokens`| `int` | Приблизительное количество токенов в выдаче. |

---

### 2. `store_memory`

Активное сохранение (ingestion) новых фактов, диалогов и знаний в векторную базу AnythingLLM.

**Параметры:**

| Параметр | Тип | Обязательный | По умолчанию | Описание |
| :--- | :--- | :---: | :--- | :--- |
| `content` | `str` | Да | - | Текст знания, факта или заметки для сохранения. |
| `title` | `str` | Нет | `None` | Заголовок/имя файла знания (например, `user_preferences.txt`). |
| `workspace` | `str` | Нет | `dmagybot` | Целевой воркспейс в AnythingLLM. |
| `metadata` | `dict` | Нет | `None` | Дополнительные метаданные в формате словаря. |
| `tier` | `str` | Нет | `semantic` | Иерархический уровень памяти (`episodic`, `semantic`, `procedural`). |

**Ответ (JSON):**

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `success` | `bool` | Статус операции. |
| `doc_id` | `str` | Идентификатор сохраненного документа. |
| `title` | `str` | Использованный заголовок. |
| `location` | `str` | Местоположение документа. |
| `workspace` | `str` | Воркспейс, куда были сохранены данные. |
| `tier` | `str` | Примененный уровень памяти. |
| `latency_ms`| `float` | Время выполнения операции. |
| `error` | `str` | (Только при `success: False`) Описание ошибки. |

---

### 3. `get_document`

Извлечение полного сырого текста документа по его `doc_id` напрямую из лексического кэша SQLite.

**Параметры:**

| Параметр | Тип | Обязательный | По умолчанию | Описание |
| :--- | :--- | :---: | :--- | :--- |
| `doc_id` | `str` | Да | - | Путь/идентификатор документа (из `search_memory`). |
| `max_chars` | `int` | Нет | `20000` | Максимальное количество символов для защиты от переполнения контекста. |

**Ответ (JSON):**

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `doc_id` | `str` | Запрошенный идентификатор документа. |
| `found` | `bool` | Найден ли документ. |
| `source` | `str` | Источник документа. |
| `title` | `str` | Заголовок. |
| `chars` | `int` | Фактическое количество символов текста. |
| `truncated` | `bool` | Был ли текст обрезан из-за `max_chars`. |
| `content` | `str` | Сырой текст документа. |
| `error` | `str` | (Только при ошибке) Описание ошибки. |

---

### 4. `gateway_health`

Проверка состояния и доступности сервисов и баз данных (Vector, Lexical).

**Параметры:** Нет.

**Ответ (JSON):**

| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `ok` | `bool` | Общий статус здоровья шлюза. |
| `token` | `dict` | Информация о токене AnythingLLM (`present`, `len`, `error`). |
| `lexical_db` | `dict` | Статус лексической БД SQLite FTS5 (`path`, `exists`). |
| `workspaces` | `dict` | Статус загрузки воркспейсов (`count`, `error`). |
| `vector_layer`| `dict` | Проверка API AnythingLLM (`reachable`, `vector_count`). |
| `vector_search`| `dict` | Реальная проверка работоспособности вектора гибридным запросом (`functional`, `degraded`).|
| `latency` | `dict` | Статистика задержек ответов AnythingLLM. |
| `message` | `str` | Человекочитаемое описание состояния или список ошибок. |

## Потоки Данных и Трансформации

### Поиск и Сборка
1. **Запрос агента**: Агент вызывает `search_memory`.
2. **Параллельные запросы**: Шлюз отправляет параллельные запросы в AnythingLLM (вектор) и SQLite FTS5 (лексика).
3. **Объединение (Fusion)**: Полученные результаты нормализуются и объединяются по взвешенному скорингу.
4. **Сборка Контекста**: Если включено, шлюз обращается к SQLite, чтобы загрузить соседние абзацы для каждого фрагмента, обогащая текст.
5. **Фильтрация и Бюджет**: Применяется фильтрация старых записей и ограничение на объем возвращаемого текста (`max_token_budget`).

### Сохранение Данных
1. **Запрос агента**: Агент вызывает `store_memory` с новым текстом.
2. **Отправка Raw-Текста**: Шлюз отправляет текст в AnythingLLM через endpoint `/api/v1/document/raw-text`.
3. **Обновление Эмбеддингов**: Шлюз инициирует синхронизацию эмбеддингов для выбранного воркспейса (`/update-embeddings`).
4. **Синхронизация**: В фоновом режиме (через внешние процессы или cron) локальная копия `lexical.db` обновляется из памяти AnythingLLM, чтобы новые документы были доступны через гибридный поиск.
